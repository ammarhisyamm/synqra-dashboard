## Implemented

- Shared `Field`, `TextField`, `TextAreaField`, and `SelectField` own form labeling, spacing, helper text, and accessible descriptions. SelectField accepts both the existing `values` API and `options`.
- Assignee and label multiselects use a portalled Radix menu with keyboard navigation, checked state, trigger-aligned width, collision handling, and component-owned CSS. Avatar and name/email layout no longer depends on visiting Board first.
- Detail drawer uses Radix focus management and a 400 px maximum width. Its fields stack on narrow viewports. Dropdown Escape closes the dropdown before the drawer.
- Removed obsolete `detail-overrides.css`; detail styles are scoped to the detail component rather than overriding form labels throughout the app.
- Serialized task-property saves, explicit load/save errors and retry, pending state for mutations, optimistic subtask toggles with rollback.
- Empty titles and invalid/negative estimates are rejected. Task-create and project-create forms preserve input after API failure.
- Assignee clearing also clears the legacy primary-assignee value on the server. Attachment links resolve through their attachment API IDs.
- My Work uses the current user's primary/secondary assignment, real collapsible groups, and a single actionable empty state instead of three empty sections.
- SQLite UTC timestamps are parsed explicitly. Waiting in Open is not counted as active-status elapsed time; active-status elapsed time is explicitly not timesheet hours.
- Calendar weekday labels now agree with its Monday-first cell layout and expose selected state.
- Dashboard/review/report due-date filters and new meeting/sprint defaults share local calendar dates rather than UTC dates that switch a day early in Jakarta.
- Settings persist `accessMode` for non-default projects and validate empty project names.
- Onboarding fields use shared components and display create errors inline.
- AI review uses shared fields for editing, explicit select-all state, and guarded creation. Partial task creation keeps only failed items for retry and reuses the saved meeting rather than creating duplicates.
- Existing linked meeting tasks suppress re-extraction of identical note drafts. Draft task creation awaits API results and retains failed drafts.
- Confirmation dialogs await their action, show errors, and disable repeated submissions while pending.
- Kanban view tabs and filter controls wrap independently at intermediate widths rather than overflowing their container.
- Mobile Kanban tabs retain their intrinsic width in an intentionally scrollable tab strip; labels no longer overlap. The detail estimate helper appears once.
- Shared Radix dialogs own focus trapping, focus return, Escape, overlay placement, white surfaces, and pending-state close protection. Metadata, sprint, create-task, collaborator, and project dialogs use shared primitives.
- Viewer access disables task creation/editing, metadata management, sprint movement, and destructive controls while leaving browsing/filtering available. Detail load retry is outside the disabled fieldset.
- Archive/restore and admin confirmations retain errors rather than closing on a failed mutation. Failed bulk changes remain selected for retry; meeting/admin creation preserves input.
- Notifications open the complete task in its correct project rather than a partial `{id,title}` object with missing permission context.
- Project-scoped invitations use hashed, expiring, email-bound, single-use acceptance links and real membership roles. Collaborator and meeting-participant invitations expose copyable links if email delivery is unavailable.
- Team lookup, metadata/sprint writes, task relations, and private-project notifications enforce project scope. Revoked access hides past private notifications and removes their unread badge.
- Task creation rejects cross-project meeting/parent/sprint references; task updates cannot silently move a task into another project. Clearing assignees clears the primary assignee too.
- HTML uses `no-store`; successful hashed bundles use immutable caching. Missing asset paths return an uncached 404 rather than SPA HTML masquerading as a script. Failed lazy imports recover through an explicit reload, not an automatic reload that discards input.

## Component ownership rules

- General field/select/dialog behavior belongs to shared components. Feature styles must not redefine global field internals.
- Portalled menus must import their own styles, match trigger width, and remain independent of route visit order.
- Use 4 px spacing increments; default field gaps 8 px, property grids 16 px, section padding 16–24 px. Let content wrap and use `minmax(0, 1fr)` for responsive grids.
- For every mutation: pending state, failure feedback, preserve input, avoid premature success/close, and verify persisted data before reporting success.
- For each regression, test cold route loads, detail-before-Board load order, keyboard interaction, and desktop/tablet/mobile widths.
