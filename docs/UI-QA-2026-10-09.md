# Synqra UI consistency and available-feature audit

Date: 2026-10-09. Base revision: `302f8a2` on `codex/office-rollout`.
Scope: currently available workspace features and shared UI, not the deferred meeting bot.
Status: implemented locally; production is unchanged by this audit.

## Reproducible findings fixed

| Finding | Fix and regression coverage |
| --- | --- |
| Export and Submit buttons touch before visiting Meetings | Page action groups now belong to the global design system, not a lazy Meetings stylesheet. Assert at least 8px separation on desktop, tablet and mobile. |
| Single-select text wraps into cramped fragments | Explicit trigger/option label wrappers. Radix Value/ItemText discard className; wrappers carry intrinsic sizing. Closed labels truncate, open options wrap. |
| Small dropdown triggers produce narrow option menus | Single-select minimum 160px, multi-select minimum 220px, wider fields retain their width. Portal collision handling, selected state, keyboard and Escape remain Radix-owned. |
| Shared controls inherit different padding/gaps | Standardized shared action, form and label spacing to the 4px grid; 16px form rows, 8px labels/actions and consistent typography. Removed the lazy secondary-button declaration. |
| Long people/menu labels overflow | Menu headings and option text can wrap; avatars and checkbox indicators retain their dimensions. |
| Task drawer has a large empty header gap | Copy-link action moved inside the drawer header instead of introducing an extra outer layout child. Compact drawer remains bounded to 400px. |
| Meeting action table clips the Due column | Meeting pane switches to labelled records at 760px container width, accounting for internal padding instead of using viewport width alone. |
| Meeting and Board cards are mouse-only | Meeting selection uses a real button; Board cards support Enter/Space, visible focus and descriptive names. |
| Board metadata runs together and priority uses a generic navy dot | Explicit metadata spacing and the shared semantic Priority component. Meeting priorities/statuses now reuse the same badges. |
| Team/Filter trigger widths differ on mobile Board | Triggers fill their available toolbar tracks. Horizontal scrolling remains intentional for the multi-column board/timeline. |
| Tablet Reports header crushes its description | Header wraps according to available width; report-definition copy follows the heading. Mobile column layout resets flex basis so it does not create a 240px empty block. |
| AI Review hides editable properties on phones | Labelled form rows preserve assignee, priority, status, due date and discard controls. Tests edit these fields at 375/768/1440px. |
| Admin and project health tables clip important columns on narrow screens | Shared responsive-record-table layout retains role/actions and report properties. Its table selector now overrides the legacy 1070px minimum width; assertions check the viewport bounds of every labelled cell, plus keyboard role confirmation. |
| Notification close/search controls lack clear names or gaps | Explicit Close notifications/Search projects labels and shared header-action spacing. |
| Supporting text and shared semantic badges have weak contrast | Darker existing blue-grey and semantic foreground tokens; shared placeholders have an automated 4.5:1 contrast check. This is not a claim that every historical literal colour meets WCAG. |

The audit follows the incumbent design.md palette/font and the Impeccable/Baseline UI guidance. It does not introduce another component library or rebuild the brand. Rules and ownership are documented in design.md to avoid route-order CSS dependencies.

## Flow and negative-case coverage

- Authentication, primary navigation, onboarding/project creation/invitation.
- My Work groups/empty state, Reviews filtering/selection, bulk updates, archive confirmation.
- Task detail: estimate, phase, status, assignees, metadata, comments, subtasks, attachments and deep links.
- Board drag persistence; List, Sprint Planning and Timeline navigation; metadata create/colour selection.
- Meeting notes/editor, AI preview property editing/selection, partial-create retries without duplicate meetings.
- Settings preferences/feedback retry and mobile administrative actions.
- Viewer restrictions, expired sessions, blocked browser storage, stale polling, project switching, malformed/unavailable bootstrap and lazy-chunk recovery.
- Failure feedback preserves drafts/input and selected failed items; dialogs trap focus and restore the opener.

Browser fixtures deliberately inject failures. A separate real local Worker/D1/R2 flow verifies actual writes, reload persistence, files and invitation isolation. No destructive tests target production.

## Limits and release handoff

- This patch has not been pushed or deployed. Local verification is not a production smoke check.
- Live email delivery, office SSO and self-hosted bot admission/recording are outside this run. The bot remains hidden; normal meeting notes stay available.
- External AI output quality/availability is not proven by deterministic test fixtures.
- Physical Safari/iOS, screen readers, browser zoom, load and exhaustive historical workspace data need separate acceptance checks. Passing these cases does not guarantee zero bugs.
- Legacy feature CSS still exists. Shared contracts and route-order regressions reduce the observed failures; this audit is not a claim that every compatibility rule has been deleted.
