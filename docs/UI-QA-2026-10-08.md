# Synqra — UI, flow, and negative-case QA
Date: 2026-10-08
Base revision: f7eae76
Status: fixes implemented, locally verified again before commit, and prepared for Git release. Production deployment is not verified by this audit.

## Outcome
Reproducible failures were fixed and regression-tested. Passing this suite is evidence for the cases below, not a guarantee that every possible production case is bug-free.

## Findings addressed

| Area | Finding | Resolution |
| --- | --- | --- |
| Workspace startup | A failed bootstrap could expose a half-loaded shell or old shared workspace cache | Gate rendering on successful bootstrap; show retry state; start from empty data; remove the old shared cache |
| Session expiry/logout | Private dialogs and workspace state could remain after authentication expired | Clear private data, notifications, selected task, dialogs and navigation on logout or API 401 |
| Background refresh | An in-flight bootstrap could overwrite a newer task save; polling could retain the initial project | Track API mutation revision/pending writes; reject stale polling responses; restart polling for the selected project |
| API responses | HTML, malformed JSON, or unexpected response shapes could be treated as a successful save | Reject invalid success responses and preserve error status; use the same client for AI and attachment uploads |
| Authentication | Duplicate submission and confusing registration copy | Pending-submit guard, accessible error alert and accurate role copy |
| All Reviews mobile | Titles/keys ran together and additional columns overflowed | Separate title/key; wrap titles; expose status, priority, stage, assignee and due date in mobile metadata |
| Meeting action items | Available pane width differed from viewport width; a lazy-loaded legacy rule restored a wide table | Container-responsive cards, labeled properties and sufficiently specific width override |
| Dropdown surface | Legacy positioning could interfere with a portalled select menu | Normalize the shared portalled menu positioning without narrowing multi-select options |
| Dialogs | Meeting date picker and command search did not share all focus behavior; pointer-trigger focus return failed in WebKit | Use shared dialog primitives; trap focus, Escape dismissal and track the actual opening control for focus return |
| Viewer UI | Command palette offered creation/admin actions inconsistent with permissions | Respect project read-only/no-project state and user role |
| Task/meeting/sprint dates | Date-shaped strings could represent impossible calendar dates; partial updates could invert stored date ranges | Calendar and merged-range validation with clear 400 errors |
| Task hierarchy | Cyclic parent relationships could be accepted | Reject self-parent, ancestor cycles and excessive hierarchy depth |
| Epic/feature relationships | Invalid or cross-project parent metadata could be assigned | Require an active epic in the same project; parent relationship only for features |
| Metadata/sprint/subtask edits | Empty names and duplicate edits produced inconsistent outcomes | Validate empty names; return conflict errors for duplicate names |
| Metadata notifications | Updates/deletes lacked explicit project scoping | Pass the item's project into notification routing |
| Auth mutation origin | Origin checks did not cover authentication mutation routes | Apply the existing explicit allowlist before auth mutations; do not loosen CORS |
| Upload/delete lifecycle | Malformed upload bodies could produce 500; task deletion could leave its R2 files behind | Return actionable 400 for malformed/empty uploads; delete associated task attachment objects |

No new database migration was required. Existing compatibility CSS remains; this audit does not claim all legacy feature CSS has been removed.

## Case coverage

| Area | Positive paths | Negative and regression cases |
| --- | --- | --- |
| Auth/onboarding | Register, empty workspace, create project, invite, finish; login/logout | Bad credentials, invalid/duplicate registration, denied browser storage, bootstrap failure/retry, expired session |
| Access control | Project owner/editor and viewer access; invitation acceptance | Unauthenticated requests, outsider access, non-admin admin routes, viewer writes, wrong-account/replayed invitation, revocation |
| Task detail | Create/edit, estimate hours, status/stage, assignee/metadata, subtask, comment, attachment, reload persistence | Failed create/save retains input and allows retry; invalid dates/relations; invalid response bodies; stale refresh cannot undo save |
| Board | Drag between stages and persist/reload; status filter | Origin allowlist rejection; clipped filter labels; viewer restrictions |
| My Work/All Reviews | Group collapse, empty state, selection/clear and bulk actions | Failed bulk operation retains failed selections; archive failure keeps confirmation open |
| Meetings/AI preview | Create meeting, preview/edit assignee/priority/status, selection and task creation | Legacy records with missing fields; partial task-creation failure retries only failed items without duplicating the meeting |
| Metadata/sprints | Shared fields, color selection and modal behavior | Empty/duplicate names, invalid dates/status, cross-project parent and invalid parent type |
| Settings/project deletion | Responsive confirmation and failure feedback | Failed deletion preserves typed confirmation; project and user isolation checks |
| Main page layout | Overview, My Work, All Reviews, Meetings, Board, Reports, Archive and Settings at 1440/768/375 px | Page overflow assertions, compact task drawer, centered create dialog, meeting pane content bounds |
| Navigation/dialogs | Search navigation, keyboard interaction and focus return | Escape, focus trapping, unavailable lazy route with explicit reload recovery |

UI tests use deterministic API fixtures to inject failures. The separate real-Worker browser flow uses actual local D1/R2 and no API mocks. The Worker integration test exercises additional backend permissions and data validation.

## Reproduce locally

Use an isolated local Worker/D1/R2, apply the repository migrations, and build fresh assets first. Do not point destructive integration tests at production.

```sh
npm run build
WORKER_TEST_URL=http://127.0.0.1:8818 WORKER_TEST_DB_DIR=/path/to/disposable/db npm test
E2E_BASE_URL=http://127.0.0.1:5318 E2E_CROSS_BROWSER=1 npm run test:e2e -- --workers=3 --output=test-results/cross-browser
E2E_REAL_WORKER=1 E2E_BASE_URL=http://127.0.0.1:8818 WORKER_TEST_DB_DIR=/path/to/disposable/db npx playwright test e2e/real-worker-flow.spec.js --workers=1 --output=test-results/real-worker
npx wrangler deploy --dry-run
```

Audit execution used a clean clone at /Users/mac/.codex/tmp/synqra-qa-20261008 because source files in the main iCloud-backed folder intermittently stalled reads/builds. The verified source changes were transferred back to the main workspace and compared byte-for-byte. Dependencies/build output were not copied over. Disposable local test data was used; no production user/project data was deleted.

Screenshots and Playwright traces are retained in the clone's ignored test-results directory, including test-results/ui-audit. These artifacts are local and are not committed application assets.

## Remaining release checks / limits

1. This report records pre-push QA. A Git push does not establish that frontend and backend deployment succeeded. Existing production availability checks do not verify the new patch in production.
2. External AI provider success/timeout behavior and actual email delivery were not exercised against paid/live providers; AI preview and injected failure handling were tested locally.
3. WebKit coverage is not a physical Safari/iOS device check. Real devices, screen readers and browser zoom/OS text scaling still merit a focused release check.
4. This was not a load, penetration, or exhaustive large-historical-workspace test. No absolute zero-bug claim is made.
5. D1 and R2 operations are not one atomic distributed transaction. Attachment cleanup on task deletion was implemented, but storage/database failure compensation and pre-existing orphan cleanup remain operational hardening work.
6. Existing administrator/project-deletion policy was preserved. This audit does not silently change organization permissions.
7. After an approved release, smoke-test login, real project invitation, task save/drag and meeting generation on the deployed origin before declaring the production release verified.
